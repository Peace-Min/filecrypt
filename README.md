# FileCrypt

파일·폴더를 **텍스트 한 덩어리**로 바꿔 복사·붙여넣기로 옮기고, 원래 파일과 폴더 구조를 그대로 되돌리는 도구.

인터넷이 없는 Windows에서 설치 없이 돌아갑니다. GUI는 .NET Framework 4.8(Windows 10/11 내장), CLI는 PowerShell 5.1 내장 기능만 씁니다.

> **먼저 알아야 할 것: 이 도구는 암호화 도구가 아닙니다.**
> 키가 소스에 박혀 있고 공개돼 있습니다. 하는 일은 **압축 · 눈으로 못 읽게 만들기 · 훼손 감지**입니다.
> 내용을 보호하지 않습니다. 자세한 내용은 [보안 수준](#보안-수준) 참고.

## 쓰는 법

### GUI — `FileCrypt.cmd` 더블클릭

```
┌ 파일 → 텍스트 ┐  텍스트 → 파일          ← 상단 토글로 방향 선택
│                                        │
│        여기로 끌어다 놓으세요            │  ← 파일·폴더 드래그
│                                        │
├────────────────────────────────────────┤
│ 파일 추가 │ 폴더 추가 │ 선택 삭제 │ 전체 삭제
│ 저장 폴더 [ C:\Users\...\Desktop ] [찾아보기]
│ ☑ 하나로 묶기   ☑ 클립보드에 복사
│                          [ 텍스트로 만들기 ]
└────────────────────────────────────────┘
```

- **폴더를 넣으면 `하나로 묶기`가 자동으로 켜집니다.**
- 실행 버튼 위에 무엇을 할지 문장으로 표시됩니다.
- 되돌릴 때는 `텍스트 → 파일` 로 바꾸고 텍스트 파일을 넣거나 `클립보드에서 가져오기`.
- 방식(블록/아카이브)은 텍스트 안에 기록되므로 **되돌릴 때 고를 것이 없습니다.**

### CLI (선택) — `engine\암호화.cmd` / `engine\복호화.cmd`

GUI를 못 쓰는 PC를 위한 예비 경로입니다. **평소에는 쓸 일이 없습니다.**

GUI와 결과가 완전히 같고 서로 만든 텍스트를 그대로 주고받습니다. 지우지 않고 남겨둔 이유는 구현이 둘이면 포맷이 자동으로 검증되기 때문입니다 — 실제로 이 덕분에 PowerShell의 `[byte] -shl 8` 버그를 잡았습니다.

## 두 가지 방식

| 넣은 것 | 방식 | 결과 |
|---|---|---|
| **파일 몇 개** | 블록 방식 | 파일마다 독립 블록. 뒤가 잘려도 앞쪽은 살아남음 |
| **폴더** | 아카이브 | 전체를 한 번에 압축한 블록 1개. 훨씬 작음 |

둘 다 폴더 구조를 보존합니다. 상대 경로가 컨테이너 안에 들어가므로 방식과 무관합니다.

```
프로젝트/                              프로젝트/
  README.md                             README.md
  src/App.cs          → 텍스트 1개 →     src/App.cs
  src/ui/App.cs                         src/ui/App.cs      ← 이름 같아도 안 겹침
  doc/보고서/최종.txt                     doc/보고서/최종.txt
```

## 왜 줄어드나

압축이 줄입니다. 암호화는 크기를 줄이지 않습니다. 순서는 **압축 → 암호화**입니다.
(반대로 하면 암호문은 엔트로피가 최대라 압축률이 0%입니다.)

```
원본 + 파일명(상대 경로)
  → Deflate 압축         (무손실)
  → AES-256-CBC
  → HMAC-SHA256 인증
  → Base64 텍스트         ← 여기서 33% 다시 늘어남
```

Base64가 33%를 되돌리기 때문에, 압축이 안 되는 데이터는 **원본보다 커집니다.**
큰 이미지·동영상·ZIP·EXE는 이 도구에 맞지 않습니다.

## 무결성

- 원본 SHA-256을 헤더에 기록하고 복호화 후 자동 대조합니다.
- 암호문 전체를 HMAC-SHA256으로 인증합니다.
- **1비트라도 상하면 깨진 파일을 뱉지 않고 복호화 자체를 거부합니다.**
- 복원되거나, 거부되거나 둘 중 하나입니다. 조용히 반쪽만 나오는 경우는 없습니다.

### 붙여넣기 내성

메일·채팅으로 오가며 생기는 변형을 견딥니다. 아래는 전부 **정상 복원**됩니다.

| 상황 | |
|---|---|
| 빈 줄 섞임 / 앞뒤 공백·탭 | 복원 |
| 제로폭 문자(U+200B) 삽입 | 복원 |
| 줄바꿈이 전부 사라져 한 줄이 됨 | 복원 |
| 다른 줄폭으로 다시 접힘 | 복원 |
| 블록 앞뒤에 인사말·본문 | 복원 |
| 메일 인용부호 `> ` 가 줄마다 | 복원 |
| `-----END-----` 줄 없음 (데이터는 온전) | 복원 |
| **뒤쪽 잘림 / 중간 줄 누락 / 1글자 변조** | **거부** |

Base64 알파벳이 아닌 문자는 버리고 읽되, 데이터가 실제로 상하면 HMAC이 잡습니다.

### 경로 공격 차단

컨테이너는 남이 만들어 보낼 수 있으므로 파일명을 그대로 믿지 않습니다.

| 텍스트에 적힌 이름 | 실제 저장 위치 |
|---|---|
| `..\..\..\Windows\System32\evil.dll` | `<저장폴더>\Windows\System32\evil.dll` |
| `C:\Windows\Temp\evil.txt` | `<저장폴더>\Windows\Temp\evil.txt` |
| `\\서버\공유\evil.txt` | `<저장폴더>\서버\공유\evil.txt` |
| `a\..\..\b\escape.txt` | `<저장폴더>\a\b\escape.txt` |

최종 경로가 저장 폴더 밖이면 예외로 막습니다. 실제 상위 폴더 덮어쓰기 시도로 검증했습니다.

## 보안 수준

**암호가 없습니다. 키는 소스에 있고 공개돼 있습니다.**

- 되는 것: 눈으로 못 읽게, 전송 중 훼손·변조 감지, 글자수 줄이기
- **안 되는 것: 내용 보호. 이 도구를 가진 사람은 누구나 엽니다.**

기밀 자료를 남이 볼 수 있는 곳(메일·메신저·게시판)에 붙여넣는 용도로는 **쓰면 안 됩니다.**
그런 용도가 필요하면 7-Zip AES-256 등 실제 암호화 도구를 쓰세요.

공개된 키에 PBKDF2 스트레칭을 거는 것은 아무것도 지키지 않으면서 파일 수에 비례해 시간만 먹으므로, 반복 횟수는 1회입니다. (헤더의 반복 횟수 필드는 남아 있어 예전에 만든 텍스트도 열립니다.)

## 실사용 가능 여부

**결론: 아래 용도에는 쓸 수 있고, 그 밖에는 권하지 않습니다.**

### 적합

- 소스코드·XML·CSV·로그·설정 파일을 **텍스트 채널로 옮기기** (메신저, 메일 본문, 게시판, 문서)
- 폴더 통째로 옮기기 (구조 보존)
- 붙여넣기 과정에서 잘리거나 상한 것을 **확실히 잡아내야** 할 때

### 부적합

| 상황 | 이유 |
|---|---|
| 기밀 유지가 필요한 자료 | 암호가 없음. 누구나 열림 |
| 이미지·동영상·ZIP·EXE 등 큰 바이너리 | 압축이 안 돼 **원본보다 커짐** (136%) |
| 수백 MB 이상 | 파일 전체를 메모리에 올림 |
| 복원 경로가 260자를 넘는 깊은 구조 | Windows 제한. 저장 폴더를 짧게 잡아야 함 |

### 알려진 한계

- **메모리**: 파일 전체 + 압축본 + 암호문을 동시에 들고 있습니다. 50 MB에서 +38 MB. 수백 MB 이상은 권하지 않습니다.
- **클립보드**: 2,000만 자까지 왕복 확인. 그 이상은 미검증이며, 생성된 `.txt`를 직접 전달하는 편이 낫습니다.
- **긴 경로**: 260자를 넘으면 그 파일만 건너뛰고 원인을 알려줍니다(종료 코드 5). 나머지는 복원됩니다.
- **잠긴 파일**: 다른 프로그램이 잡고 있으면 그 파일만 건너뛰고 개수를 보고합니다.
- **아카이브 부분 복원 불가**: 폴더를 아카이브로 묶으면 텍스트가 조금만 상해도 전부 못 씁니다. 블록 방식은 앞쪽이 살아남습니다.
- **GUI 창 자체는 자동 테스트가 없습니다.** 암복호화 코어와 폴더 순회는 테스트가 덮지만, 버튼·드래그드롭 같은 UI 조작은 수동 확인이 필요합니다.

## 폴더 구성

```
filecrypt\
  FileCrypt.cmd               ← 이것만 쓰면 됩니다 (GUI 실행)
  README.md
  gui\
    FileCrypt.csproj          .NET Framework 4.8 WPF
    FileCryptCore.cs          압축·인증 코어
    MainWindow.xaml(.cs)      UI
  engine\                     ← 예비 CLI + 검증용. 평소 볼 일 없음
    암호화.cmd  복호화.cmd
    simple.ps1  filecrypt.ps1
    tests\                    검증 스위트 8종
```

GUI 빌드 (최초 한 번):

```powershell
cd gui
dotnet build -c Release
```

결과는 `gui\bin\Release\net48\FileCrypt.exe` (36 KB).
빌드 후에는 최상위 `FileCrypt.cmd` 로 실행하거나, **exe 파일 하나만 복사**해서 다른 PC에서 그대로 쓰면 됩니다. .NET Framework 4.8은 Windows 10/11에 내장돼 있어 별도 설치가 필요 없습니다.

## 컨테이너 형식

헤더 112바이트 + 암호문.

| offset | size | 내용 |
|---|---|---|
| 0 | 8 | magic `FCRYPT01` |
| 8 | 1 | version (2) |
| 9 | 1 | flags — bit0 압축됨, bit1 PBKDF2-SHA256, **bit2 아카이브** |
| 10 | 2 | 예약 |
| 12 | 16 | salt |
| 28 | 16 | IV |
| 44 | 4 | PBKDF2 반복 (int32 LE) |
| 48 | 32 | 원본 SHA-256 (아카이브면 페이로드 전체) |
| 80 | 32 | HMAC-SHA256 (헤더 0~79 + 암호문) |
| 112 | .. | 암호문 |

페이로드 (단일):
```
[uint16 이름길이][이름 UTF-8][원본 바이트]
```

페이로드 (아카이브, flags bit2):
```
[int32 개수]
반복: [uint16 이름길이][이름 UTF-8][int64 크기][내용]
```

## 엔진 직접 호출

```powershell
.\engine\filecrypt.ps1 -Mode Encrypt -Path data.xml -Armor -Width 100
.\engine\filecrypt.ps1 -Mode Encrypt -Folder .\프로젝트 -Armor -Width 100   # 아카이브
.\engine\filecrypt.ps1 -Mode Decrypt -Path data.xml.enc.txt -OutDir .\복원
```

| 옵션 | 설명 |
|---|---|
| `-Path` | 입력 파일 |
| `-Folder` | 폴더 전체를 아카이브 1블록으로 |
| `-Name` | 컨테이너에 기록할 이름 (상대 경로 지정용) |
| `-Out` / `-OutDir` | 출력 파일 / 출력 폴더 |
| `-Armor` / `-Width N` | Base64 텍스트 출력 / 줄폭 (`0` = 한 줄) |
| `-Compress Off` | 압축 끄기 |
| `-Force` | 덮어쓰기 허용 |
| `-Quiet` | 결과 경로만 출력 (스크립트용) |

종료 코드: `0` 성공 · `1` 오류 · `2` 취소 · `4` **인증 실패(손상/변조)** · `5` 일부 항목 건너뜀
