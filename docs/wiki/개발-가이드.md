# 개발 가이드

[← 위키 처음](Home.md)

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `gui/` | WPF 앱(.NET Framework 4.8, x64). 버전은 `FileCrypt.csproj` 의 `<Version>` 한 곳 |
| `gui/FileCryptCore.cs` · `FileCryptJobs.cs` | 변환 코어 · 창이 부르는 처리 절차(UI 없음, 시험 가능) |
| `gui/FolderTree.cs` · `ShellIcons.cs` | 왼쪽 폴더 트리 로직(UI 없음) · 탐색기 아이콘 |
| `gui/Netcus*.cs` | 근태관리 연동. `NetcusService.cs` 는 캘린더에서 가져온 것 + FileCrypt 추가분(`NetcusService.FileCrypt.md`/`.patch`) |
| `engine/` | PowerShell 예비 CLI(`filecrypt.ps1`, `simple.ps1`) — GUI 와 형식을 교차 검증하려고 일부러 따로 구현 |
| `engine/tests/` | 시험 스위트 + `run-all.ps1` + `ui/`(실제 창 UI 시험) |
| `tools/netcus-mock/` | 목업 근태관리 사이트 |
| `installer/` | Inno Setup 스크립트와 설치 파일 만들기 |
| `docs/` | `specs/`(기획) · `qa/`(시험 결과) · `wiki/`(이 문서) |

## 빌드

```powershell
dotnet build gui\FileCrypt.csproj -c Release
```

결과: `gui\bin\Release\net48\FileCrypt.exe` + DLL 13개(WebView2·System.Text.Json 계열). exe 만 옮기면 근태관리 창이 죽습니다.
`FileCrypt.cmd` 는 설치본과 빌드본 중 새것을 띄웁니다.

## 시험

```powershell
powershell -ExecutionPolicy Bypass -File engine\tests\run-all.ps1          # 전체 (약 3분)
powershell -ExecutionPolicy Bypass -File engine\tests\run-all.ps1 -Quick   # 대용량(test-limits) 빼고
powershell -ExecutionPolicy Bypass -File engine\tests\run-all.ps1 -Only jobs,split
powershell -ExecutionPolicy Bypass -File engine\tests\run-all.ps1 -UI      # + 실제 창 UI 시험
```

- 시험 전에 Release 빌드가 있어야 합니다(스위트가 빌드된 exe 를 불러 **실제 배포물**을 시험).
- 스위트마다 `%TEMP%\fc_*` 작업 폴더와 격리 설정 폴더(`FILECRYPT_DATA_DIR`)를 쓰고 끝나면 지웁니다(`FC_KEEP_WORK=1` 이면 남김).
- 공통 도우미: `engine\tests\_common.ps1` (`Start-Test`, `Ok`, `Import-FileCrypt`, `Complete-Test`).
- **UI 시험**(`engine\tests\ui\`)은 UIAutomation 으로 창을 누르고 SendKeys 로 입력합니다. 앱 창이 포커스를 가져가니 **도는 동안 입력하지 마세요**. 탐색기는 열지 않고(`FILECRYPT_NO_EXPLORER=1`) 클립보드 복사는 끕니다.
- 클립보드 시험은 다른 프로그램이 클립보드를 잡으면 가끔 실패합니다 — 그 스위트만 다시 돌려 봅니다.

### 근태관리: 목업 사이트

실제 사이트 없이 올리기·가져오기 전체 흐름을 돌립니다(`engine\tests\test-netcus-mock.ps1`, 41건).

```powershell
powershell -ExecutionPolicy Bypass -File tools\netcus-mock\start-mock.ps1   # 목업 + 앱을 띄워 직접 눌러 보기 (mock / mock1234)
```

- 앱은 `FILECRYPT_NETCUS_MOCK=<포트>` 일 때만 `www.netcus.com` 을 `127.0.0.1` 로 돌립니다(창 제목에 `[목업]`).
- 장애 주입: 저장 잘림, 기록 버림, 세션 만료, 로그인 차단, 무응답, 주 52시간 거부. 자세한 것은 `tools\netcus-mock\README.md`.
- 목업은 **아는 동작만** 재현합니다. 사이트와 맞닿는 코드를 바꾸면 실제 사이트에서 지난 날짜 1~2일로 확인합니다.
  읽기만 하는 확인: `FileCrypt.exe --netcus-selftest 시나리오.json` 에 `op: "plan"`. 실제 쓰기는 `allowDates` 에 적은 날짜에만.
- 사이트 구조가 바뀐 것 같으면 `FileCrypt.exe --netcus-capture` 로 다시 떠서 비교합니다(읽기 전용, 로그인은 사람이, 결과는 저장소에 넣지 않음).

## 설치 파일과 릴리즈

| 하려는 것 | 실행 |
|---|---|
| 지금 소스로 설치 파일만 | `installer\설치패키지만들기.cmd` (버전·커밋 그대로, git 실패해도 만듦, 끝나면 폴더 열기) |
| 버전 올려 배포 | `installer\setup만들기.cmd` (`-Bump` patch · minor · major · none). 커밋 안 된 수정이 있으면 멈춤 → 버전 올리고 csproj 만 커밋 → 빌드 → 설치 파일 |
| 릴리즈 | 태그 `v<버전>` 을 푸시하고 `gh release create v<버전> installer\Output\FileCrypt-Setup-<버전>.exe` |

Inno Setup 6(`ISCC.exe`)과 dotnet SDK 가 필요합니다. 설치 파일의 버전은 빌드된 exe 에서 읽습니다.

## 기능 개발 절차

1. **기획** — `docs/specs/<기능>.md`: 배경, 목표, 시나리오, 요구사항(FR/NFR 번호), 범위 밖, 완료 기준.
2. **개발** — 로직은 UI 없는 클래스로 떼어(`FileCryptJobs`, `FolderTree`, `NetcusPlan`, `NetcusJobs`) 단위 시험을 붙입니다. 창은 묻고 알리기만.
3. **QA** — `docs/qa/<기능>-QA.md`: 요구사항마다 확인 방법과 결과, 찾은 결함과 조치, 남은 한계. 화면 동작은 `engine\tests\ui\` 에 UI 시험으로.
4. **위키** — `docs/wiki/` 의 사용자 페이지와 이 문서를 갱신합니다.
