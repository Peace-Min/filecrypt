## 1. 시험 방법

| 구분 | 무엇으로 | 어디 |
|---|---|---|
| 단위 | 사이트·창 없이 로직만: `FileCryptJobs.ParsePaths`, `FolderTree` | `engine/tests/test-jobs.ps1` (85건 중 이번 기능 23건: 경로 10 · 트리 13) |
| UI | **실제 창**을 UI 자동화(UIAutomation)로 누르고 SendKeys 로 입력. 목록 행·트리 상태·버튼 활성·상태줄을 읽어 판정 | `engine/tests/ui/test-ui-filelist.ps1` (46건) |
| 회귀 | 기존 전 스위트 | `engine/tests/run-all.ps1` |

UI 시험은 앱 창이 포커스를 가져가므로 기본 실행에서 빠져 있고 `run-all.ps1 -UI` 로 돈다.
설정은 격리 폴더(`FILECRYPT_DATA_DIR`), 탐색기는 열지 않게(`FILECRYPT_NO_EXPLORER=1`) 하고, 클립보드 복사를 꺼서
사용자의 클립보드를 덮지 않는다.

## 2. 결과 요약

```
run-all.ps1 -UI    15개 스위트 635건
  1차: 633 통과 / 2 실패 (test-limits, test-simple 의 클립보드 항목)
  재실행: 그 2개 스위트 45/45 통과
```

실패 2건은 둘 다 **PowerShell 클립보드** 항목이고 이번 기능과 관계없다. 클립보드는 시스템 전체가 함께 쓰므로
시험 도중 다른 프로그램(또는 사용자)이 잡고 있으면 읽기가 비어 온다. 같은 실행에서 바로 뒤의 "클립보드로 복호화" 와
WPF 클립보드 2천만 자 항목은 통과했고, 재실행에서 두 스위트 모두 통과했다 → 환경 요인으로 판정.

## 5. 남은 한계 · 확인하지 못한 것

- **상태 열 정렬 중 폴더를 끄면** 그 행이 바로 자리를 옮기지 않는다(머리글을 다시 눌러야). 기획 6절 범위 밖으로 둔 것.
- **드래그 앤 드롭**으로 폴더를 넣는 경로는 UI 자동화로 시험하지 않았다(끌어 놓기를 자동화하기 어렵다). 넣은 뒤의 처리는 경로 입력과 같은 함수(`AddPathsAsync`)다.
- **[근태관리로 올리기] 에서 제외가 빠지는지**는 창에서 끝까지 누르지 않았다. 버튼이 [텍스트로 만들기] 와 같은 입력 목록(`PackInputs`)을 쓰는 것을 코드로 확인했고, 전부 끄면 버튼이 꺼지는 것은 UI 로 확인했다.
- 아이콘 그림이 탐색기와 "같은지" 는 사람 눈으로 본 것이다(셸이 주는 그대로 그리므로 자동 대조하지 않음).
- 클립보드 시험은 다른 프로그램이 클립보드를 잡으면 가끔 실패한다(2절). 실패하면 그 스위트만 다시 돌려 본다.
