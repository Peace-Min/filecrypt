## 1. 배경

FileCrypt 로 옮기는 것은 대개 **프로젝트 폴더 통째**(소스·문서·빌드 결과가 섞인 수십~수천 개)다. 그때 불편했던 것:

1. 넣을 파일의 경로를 이미 알고 있는데(메신저·문서에서 복사) 파일 선택 창을 열어 폴더를 찾아 내려가야 했다.
2. 목록이 넣은 순서로만 보여서, 확장자별로 무엇이 들어 있는지 파악하기 어려웠다.
3. 폴더를 통째로 넣으면 `bin`, `obj`, 큰 산출물처럼 **옮길 필요 없는 하위 폴더**까지 들어갔다. 빼려면 목록에서 하나씩 골라 지우거나, 처음부터 폴더를 따로따로 넣어야 했다.
4. 목록이 글자뿐이라 파일 종류가 한눈에 들어오지 않았다(탐색기와 달랐다).

## 2. 목표

- 경로를 알면 **붙여넣고 Enter** 로 바로 넣는다.
- 목록을 **열 머리글 클릭**으로 정렬한다(특히 확장자).
- 넣은 파일의 폴더 구조를 **왼쪽 트리**로 보여 주고, **체크한 폴더의 파일만 처리**한다.
- 폴더·파일 아이콘을 **탐색기와 같게** 보인다.

## 3. 사용자 시나리오

**S1. 경로로 넣기** — 동료가 메신저로 `"D:\공유\보고서\8월.xlsx"` 를 보냈다. 경로 칸에 붙여넣고 Enter → 목록에 들어간다.
탐색기에서 여러 파일을 "경로로 복사" 해 붙여넣어도 한 번에 들어간다.

**S2. 확장자로 훑어보기** — 프로젝트 폴더를 넣고 "확장자" 머리글을 누른다 → `cs`, `csproj`, `dll`, `exe`, `md` … 순으로 모여 무엇이 섞였는지 바로 보인다.

**S3. 필요 없는 폴더 빼기** — 프로젝트 폴더를 넣으니 왼쪽 트리에 `LS_MIN > Core, Net > bin, doc` 이 보인다. `bin` 체크를 끄면 그 안 파일이 목록에 흐리게 "제외" 로 남고, [텍스트로 만들기] 를 누르면 나머지만 묶인다.
나중에 파일을 더 넣어도 `bin` 은 꺼진 채다.

**S4. 일부만 남기기** — 트리 [해제] 로 전부 끈 뒤 `doc` 만 켠다 → 문서만 근태관리로 올린다.

## 4. 기능 요구사항

### FR-1 경로로 추가

| ID | 요구사항 |
|---|---|
| FR-1.1 | 버튼 줄 아래에 "경로" 입력 칸과 [경로 추가] 버튼을 둔다. 비어 있을 때는 입력 예시를 흐리게 보인다. |
| FR-1.2 | Enter = 추가, Shift+Enter = 줄바꿈. |
| FR-1.3 | 여러 경로: 줄바꿈 · `;` · 탭으로 구분. 따옴표로 감싼 경로(탐색기 "경로로 복사")는 따옴표 단위로 나눈다. 경로 안의 공백은 그대로 둔다. |
| FR-1.4 | `%USERPROFILE%` 등 환경변수를 푼다. `/` 구분자, 폴더 끝의 `\` 를 허용한다. 같은 경로가 여러 번이면 한 번만. |
| FR-1.5 | `C:\…` 또는 `\\서버\…` 로 시작하는 **절대 경로만** 받는다. 상대 경로, `C:abc`, `\abc` 는 어디를 뜻하는지 모호해 거부한다. |
| FR-1.6 | 파일과 폴더 모두. 지금 탭의 추가 규칙을 그대로 따른다(폴더면 하위 전체, 복원 탭이면 `.txt` 만, 이미 있는 파일은 다시 넣지 않음). |
| FR-1.7 | 없는 경로·절대 경로 아님은 이유와 함께 상태줄에 알리고, **문제 있는 경로만 칸에 남긴다**(고쳐서 다시 Enter). |
| FR-1.8 | 작업 중에는 칸과 버튼을 잠근다. |

### FR-2 정렬

| ID | 요구사항 |
|---|---|
| FR-2.1 | 목록에 **확장자** 열(소문자, 점 없이)을 둔다. |
| FR-2.2 | 열 머리글(상태 · 파일 · 확장자 · 크기 · 위치)을 누르면 그 기준 오름차순, 같은 머리글을 다시 누르면 내림차순. |
| FR-2.3 | 정렬 중인 머리글에 ▲(오름) / ▼(내림)을 표시한다. |
| FR-2.4 | 같은 값끼리는 파일 이름순(2차 기준). 크기는 바이트 수로 비교한다(표시 문자열이 아니라). |
| FR-2.5 | 탭마다 정렬을 따로 기억한다. 나중에 넣은 파일도 정렬된 자리에 들어간다. |
| FR-2.6 | 정렬은 보이는 순서만 바꾼다. 처리 순서·결과에는 영향이 없다. |

### FR-3 폴더 트리 (파일 → 텍스트 탭)

| ID | 요구사항 |
|---|---|
| FR-3.1 | 목록 왼쪽에 "폴더" 패널을 둔다. 목록이 비어 있거나 복원 탭이면 숨긴다. 가운데 경계선을 끌어 폭을 바꿀 수 있다. |
| FR-3.2 | 넣은 파일들의 폴더로 트리를 만든다. 맨 위에서 파일 없이 하위 폴더 하나로만 이어지는 단계(`C:\Users\…`)는 건너뛰고, 파일이나 갈래가 처음 나오는 폴더부터 보인다. 드라이브가 다르면 맨 위가 따로. |
| FR-3.3 | 노드: 체크박스 · 폴더 아이콘 · 이름 · (하위까지 합친 파일 수). 마우스를 올리면 전체 경로. 하위 폴더는 이름순. |
| FR-3.4 | 체크박스를 누르면 그 폴더와 **하위 폴더 전체**가 함께 켜지거나 꺼진다. |
| FR-3.5 | 상태: 전부 켜짐 ☑ / 전부 꺼짐 ☐ / 섞임 ■. 섞임에서 누르면 전부 켜진다. |
| FR-3.6 | 꺼진 폴더에 **바로 들어 있는** 파일은 처리에서 뺀다. 목록에서는 지우지 않고 흐리게, 상태 "제외" 로 보인다. |
| FR-3.7 | [텍스트로 만들기] · [근태관리로 올리기] 는 켜진 파일만 쓴다. 파일 수 표시("N개 · 처리 M개 (제외 K개)")와 계획 줄(파일 수·크기)도 켜진 파일 기준. |
| FR-3.8 | 전부 꺼지면 실행 버튼을 끄고 계획 줄에 "왼쪽 폴더에서 처리할 폴더를 체크하세요" 를 보인다. |
| FR-3.9 | [모두] = 전부 켬, [해제] = 전부 끔. |
| FR-3.10 | 파일을 더 넣거나 일부를 지워 트리가 다시 만들어져도, 꺼 둔 폴더는 꺼진 채로 둔다. [전체 삭제] 하면 잊는다. |
| FR-3.11 | 작업 중에는 트리를 잠근다. |
| FR-3.12 | 키보드: 트리에서 폴더를 고르고 Space 로 체크를 켜고 끈다. |

### FR-4 아이콘

| ID | 요구사항 |
|---|---|
| FR-4.1 | 트리 노드에 Windows 폴더 아이콘. |
| FR-4.2 | 목록 "파일" 열 이름 앞에 그 파일 종류의 아이콘(탐색기와 같게, 그 PC 에 등록된 프로그램 기준). |
| FR-4.3 | `.exe` · `.ico` · `.lnk` 등 파일마다 아이콘이 다른 종류는 그 파일에서 꺼낸다. 그 밖은 확장자마다 한 번만 받아 캐시한다(디스크를 읽지 않음). |
| FR-4.4 | 아이콘을 못 받으면 아이콘 없이 이름만 보인다(목록은 항상 보여야 한다). |

## 5. 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-1 | 파일 2,000개를 넣어도 트리 만들기 · 체크 전환 · 정렬이 멈춘 듯 느껴지지 않는다(각각 1초 이내). |
| NFR-2 | 아이콘 조회는 확장자 수만큼만 한다. |
| NFR-3 | 트리·정렬 로직은 WPF 없이 테스트할 수 있다(`FolderTree`, `FileCryptJobs.ParsePaths`). |
| NFR-4 | 기존 동작(묶기·되돌리기·근태관리·조각내기)과 결과물 형식은 바뀌지 않는다. |

## 6. 범위 밖

- 복원 탭의 폴더 트리 — 조각 텍스트 일부를 빼면 복원이 깨진다.
- 파일 하나하나의 체크박스 — 목록 [선택 삭제] 로 충분하다.
- 꺼 둔 폴더를 앱을 껐다 켜도 기억하기 — 목록 자체가 기억되지 않는다.
- 상태가 바뀐 행의 실시간 재정렬(상태 열로 정렬한 뒤 폴더를 끄면 다시 머리글을 눌러야 순서가 바뀐다).

## 7. 완료 기준

1. FR-1 ~ FR-4 의 각 항목이 QA 문서의 시험 항목으로 확인된다.
2. 자동 테스트(`engine\tests\run-all.ps1`) 전체 통과, 새 로직(`ParsePaths`, `FolderTree`)에 단위 테스트가 있다.
3. 실제 창에서 S1 ~ S4 가 된다(UI 자동화로 확인).
4. 위키에 사용법이 있다.
